# Cycle Definition (1사이클 정의)

<!-- Intake-time agent behavior rule (L1, cf. docs/rules/scope_self_detect_policy.md).
     Lives in .omp/rules/ as a harness-* rulebook file (not docs/rules/) deliberately: the
     harness-sync whitelist ships .omp/rules/harness-*.md, so consumer repos receive this policy. -->

## 목적

지시 문서(scratchboard 등) 기반 워크플로와 소형 컨텍스트 창(≤272k) 모델 운용에서,
세션 하나가 받는 작업 단위 — **1사이클** — 를 정의한다. 에이전트는 **지시를 받은
시점(턴 1)**에 이 정의로 판정하고, 1사이클이 아니면 구현에 들어가기 전에 분할을
역제안한다.

`scope_self_detect_policy.md`(L1)와 같은 **에이전트 행동 규칙**이다 — 코드 게이트가
아니다. 기계적 backstop은 review-gate의 high-risk 임계(>100 LOC, migration/auth 등)가
커밋 시점에 간접 수행한다.

배경 실측(2026-07-30 하네스 부하 점검): 사이클 분리 없는 마라톤 세션은 소형 창에서
자동 컴팩션(272k 모델 실측 229k 발동) → 읽은 파일 소실 → 재독의 복리 비용을 만든다
(단일 파일 166회 재독 사례). 사이클 단위 세션 분리가 이 루프를 구조적으로 제거한다.

## 정의 (MUST)

**1사이클** = 아래 3항을 **모두** 만족하는 작업 단위.

| # | 기준 | 판정 질문 |
|---|------|----------|
| 1 | 완료 확인 문장 존재 | 명령 1회 실행 또는 화면 1회 확인으로 판정 가능한 **한 줄**을 쓸 수 있는가 |
| 2 | 산출물 단수 | 산출물 나열에 "~와/과"가 필요 없는가 |
| 3 | 1세션 완결 규모 | 탐색+구현+검증이 컴팩션 도달 전에 끝나는가 |

**정의가 아닌 것**: 변경 크기·리스크(LOC, migration/auth 파일 여부)는 사이클의
**비용 속성**이지 정의가 아니다. 반례: "퇴사자 본인 기록 열람 RLS 추가"는 migration을
건드리는 high-risk지만 완벽한 1사이클이다(확인: 퇴사자 계정 SELECT 성공) — 커밋 시
리뷰 증거 비용이 예고될 뿐이다. 단 **인테이크 시점**에는 냄새로 쓴다: 지시가
high-risk 커밋을 함의하면 분할을 *의심*한다(어차피 커밋에서 review-gate에 걸릴
규모면 시작 전에 쪼개는 편이 싸다).

## 판정 방법 (MUST) — 체크가 아니라 산출

기준 1을 체크리스트로 판정하지 말고 **확인 문장을 먼저 써 본다**. 모호한 확인
문장("잘 작동한다")은 사용자에게 그대로 노출되고, 아예 쓸 수 없으면 판정이 자동으로
뒤집힌다. 출력 형식(고정):

```
판정: 1사이클 | 분할 제안 | 확인문장 필요
확인 문장: <한 줄 — 실행/관찰 가능. 못 채우면 판정을 "1사이클"로 둘 수 없다>
예상: 위험 <low|medium|high|critical> / 파일 <n> / 깊이 <low|high>
```

### 예상 레코드 (MUST — 1사이클 판정 시)

`예상:` 줄의 값은 **예측**이며 실측이 아니다. 판정이 "1사이클"이면 같은 값을
`.omp/harness-state/cycle-estimate`에 한 줄 JSON 튜플로 기록한다(기존 one-shot 플래그
관례: JSON 튜플 + 버전 태그):

```
["omp-estimate/v1", <risk>, <files>, <depth>, <model>, <effort>, <ts>]
  risk   : "low" | "medium" | "high" | "critical"   — risk-assess taxonomy 그대로 (폭발 반경)
  files  : 정수 (예상 변경 파일 수)
  depth  : "low" | "high"                            — 추론 깊이. risk와 독립 축 (500줄 기계적 rename = high/low, 20줄 동시성 버그 = medium/high)
  model  : 문자열 (세션이 아는 값, 예: "claude-fable-5-1")
  effort : 문자열 또는 null (예: "medium", "high")
  ts     : ISO 8601 날짜-시각 + 존 지정자 (예: "2026-09-18T02:00:00Z" — `date -u +%Y-%m-%dT%H:%M:%SZ`)
```

커밋이 착지하면 review-gate가 이 레코드를 `risk-assess` 실측과 붙여
`docs/harness/audit.jsonl`에 `estimate_vs_actual` 이벤트로 남기고 소비한다.
레코드는 **어떤 게이트의 판정에도 관여하지 않는다** — 예측 기반 완화는 금지.
목적은 자동 라우팅이 아니라 몇 달 뒤 `harness-agent_routing.md`의 모델·에포트 기준을 실측
근거로 갱신할 원자료다(`.omp/extensions/harness/estimate-report.mjs`로 읽는다).

**사이클 미만(오타 수정 등)은 판정과 함께 레코드도 생략한다** — 과잉 발동 금지 조항과
같은 경계. 분할 제안·확인문장 필요 상태에서는 아직 쓰지 않고, 합의된 사이클이 시작될
때(사이클마다 1건) 쓴다. 하나의 커밋에 여러 사이클이 실리면 마지막 레코드만 대조된다
(one-shot).

**AC는 커밋 시점에 판정 가능해야 한다** — 범프 태그·배포·머지처럼 그 커밋 *뒤에* 생기는 것은
AC가 아니라 후속 절차로 적는다(`- … 는 이 AC의 판정 대상이 아님`). 커밋 전에 `[x]`로 체크할
수 없는 AC는 acceptance-gate 통과를 위해 거짓 체크를 유도한다(2026-09-24 실측: 3-pass 리뷰가
"2026.80 태그" AC의 선체크를 medium으로 지적, `AC5-bump-ready`로 재작성).

## 인테이크 프로토콜

판정 결과별 행동:

1. **1사이클** → 그냥 진행한다. 매번 묻는 에이전트는 사용자에게 더 해롭다.
2. **사이클 미만** (오타 수정, 1줄 변경 등) → 판정 자체를 생략하고 즉시 진행한다
   (과잉 발동 금지).
3. **분할 제안** → 열린 질문이 아니라 **안이 포함된 역제안**을 한다: 사이클
   분할안(번호 + 각 사이클의 확인 문장)을 제시하고 승인/수정을 번호로 받는다.
   합의된 분할의 기록 위치는 지시 채널에 따라 다르다 — 아래 "지시 채널" 절 참조.
4. **확인문장 필요** (경계) → 확인 방법을 함께 만들어 1사이클로 **승격**시키는
   질문을 한다. 되묻기의 목적은 게이트가 아니라 승격이다.
5. **프로젝트/신규 기능급 스코프** → kickoff(`../../.omp/skills/kickoff/SKILL.md`)를
   추천한다 — 인터뷰가 seed/AC까지 산출하는 무거운 정식 경로.

**그레이존 규칙**: 애매하면 분할 제안 쪽으로 기운다. 단 **제안은 1회** — 사용자가
"그냥 진행"을 선택하면 재론하지 않는다.

역제안 예:

> 이 작업은 확인 가능한 완료 기준이 없고 3개 영역을 건드립니다. 이렇게 나눠
> 진행하길 제안합니다:
> ① RLS 마이그레이션 — 확인: 퇴사자 계정으로 본인 기록 SELECT 성공
> ② 열람 페이지 — 확인: /history에서 과거 기록 렌더
> ③ 접근 가드 — 확인: 퇴사자가 캘린더 접근 시 차단 후 안내 표시
> 이대로 지시 문서에 기록하고 ①부터 시작할까요? (수정할 부분은 번호로)

## 지시 채널 (채팅 vs 지시 문서)

판정은 **채널 무관**이다(MUST) — 채팅 라인으로 받은 지시도 지시 문서(scratchboard 등)를
통해 받은 지시와 동일하게 판정한다. 채널은 **합의된 분할의 기록 위치**만 바꾼다.

| 상황 | 기록 위치 |
|------|----------|
| 지시 문서가 있음 | 그 문서의 사이클 큐 ([`templates/scratchboard.md`](../../templates/scratchboard.md) 형식) |
| 문서 없음 + 이번 세션에서 완결 | todo 도구로 충분 (세션과 함께 소멸해도 무방) |
| 문서 없음 + 다세션 규모(2사이클 이상) | 영속 큐 생성을 제안 — 템플릿 복사 또는 `docs/harness/current-scope.md`의 AC 체크박스(acceptance-gate 연동) |

다세션 사이클 운영은 **영속 큐가 전제**다: `/clear`는 채팅에서 합의한 분할을 지우므로,
큐가 파일로 없으면 다음 세션이 이어받을 수 없다.

**기계 백스톱의 커버리지 분담**: kickoff-detector는 채팅 프롬프트 텍스트만 보므로 채팅
지시가 주 커버 대상이다. 반대로 "스크래치보드 보고 진행해"처럼 트리거 단어가 프롬프트에
없는 문서 매개 지시는 detector가 침묵할 수 있다 — 그 경로의 백스톱은 스크래치보드 템플릿
헤더의 고정 지시 4항이 담당한다. 규칙(L1) 자체는 양 채널을 모두 덮는다.

## 경계 패턴 4종 (⚠️ 계열이 가르치는 것)

1. **조사=사이클** — 원인 불명 버그는 조사 자체가 1사이클(산출물 = 원인 판정 문서).
   수정은 다음 사이클.
2. **역제안** — 요구의 *방식* 자체가 협의로 바뀔 수 있다(자동 환기 → 사람-in-loop 버튼).
3. **수정 0건 닫기** — "정상 판정"도 완결된 사이클이다. 코드를 바꿔야만 닫히는 게 아니다.
4. **질문→기능 승격** — "~된 거 맞아?"는 검증 사이클로 받고, 그 과정에서 드러난
   기대는 별도 사이클로 승격한다.

**보류 규율**: 이번 사이클에서 의도적으로 하지 않는 것을 지시 문서에 명시한다
(실례: "대체 문장 선택은 의도적 보류" — ajoshplayer sum 2026-07-10).
