# 핸드오프 — scratchboard를 사이클 큐로 재편하기

> 대상: highgrowcorp 인수 작업자 / 작성: 2026-07-30 / 근거 하네스: harness/2026.70

## 결론 먼저

지금 방식(scratchboard에 지시 적고 → 구현 → 문서 최신화)은 그대로 유지하셔도 됩니다.
바꾸는 것은 두 가지뿐입니다: **① scratchboard의 구조**(아래 3단계), **② 세션 습관 하나**
(에이전트가 "/clear 하세요"라고 하면 /clear). 판정·분해·기록은 전부 에이전트가 합니다.

이유(실측): 272k 컨텍스트 모델은 세션이 길어지면 ~229k에서 자동 압축이 발동해 읽었던
파일이 지워지고, 다시 읽는 비용이 복리로 붙습니다(한 파일을 166회 재독한 세션도
있었습니다). 지시 1건 = 세션 1개로 끊으면 이 루프가 구조적으로 사라집니다.

## 1단계 — 하네스 동기화 (1회)

```bash
bash scripts/harness-sync.sh        # 또는 에이전트에게 "harness-check 해줘"
```

`harness/2026.70`이 받아지면 다음이 생깁니다:
- `rules/cycle_definition.md` — 1사이클 판정 규칙(정의·예시 17건). 에이전트가 자동 적용.
- `templates/scratchboard.md` — 아래 재편의 기준 형식.
- 커밋 성공 시 "사이클 경계 — 문서 갱신 + /clear 안내" 자동 알림.

## 2단계 — scratchboard.md 재편 (1회, 에이전트에게 맡겨도 됨)

현행 파일의 섹션을 이렇게 옮깁니다 (`templates/scratchboard.md` 형식 기준):

| 현행 섹션 | 이동/변환 |
|---|---|
| 기술 스택 / 프로젝트 구성 / 권한 / 스키마 / 구조 | "현재 상태" 요약표로 **압축** (자세한 건 코드가 진실) |
| 완료된 작업 내역 (Phase 1~7) | `docs/archive.md`로 **전부 이동** — scratchboard에 누적 금지 |
| 다음 작업 / 검토 필요 사항 | **사이클 큐**로 변환 (아래 예시) |
| 작업 지시 메모 | 그대로 유지 — 쓰는 방식 동일 |

현행 백로그의 변환 예시 (확인 문장이 핵심입니다):

```markdown
## 사이클 큐
- [ ] C1: 태블릿(iPad) 캘린더 레이아웃 보정 — 확인: iPad 뷰포트(768/1024)에서 월 그리드 셀 겹침 0
- [ ] C2: 스케줄 확정 푸시 알림 — 확인: 확정 이벤트 발생 시 대상 기기에 알림 1건 수신
- [ ] C3: 월별 근무시간 통계 대시보드 — 확인: 특정 월 선택 시 직원별 근무일수 합계가 DB 집계와 일치
```

## 3단계 — 운영 루프 (매 지시)

1. "작업 지시 메모"에 평소처럼 적습니다. 크기 고민은 하지 마세요 —
   에이전트가 1사이클인지 판정하고, 크면 **분할안을 번호로 역제안**합니다. 번호로 답하시면 됩니다.
2. 에이전트는 큐의 **미완료 사이클 1개만** 진행하고 커밋합니다.
3. 커밋 후 에이전트가 문서를 갱신하고 `/clear`를 안내합니다 → **/clear 치고 다음 지시**. 이게 전부입니다.

## 알아두면 좋은 것 두 가지

- **고위험 커밋 차단**: 이 프로젝트의 RLS·migration 파일을 건드리는 커밋은 하네스가
  리뷰 증거를 요구합니다. 차단 메시지가 알려주는 **human review 경로**가 가장 쌉니다 —
  diff를 직접 읽고, 메시지에 인쇄된 JSON 한 줄을 본인 이름으로 저장하면 통과입니다(토큰 0).
  단, 이름을 적는 순간 그 diff는 본인이 읽었다는 뜻입니다.
- **kickoff 리마인더**: "만들어줘/구현해줘"류 지시에 안내 1줄이 뜰 수 있습니다. 무해하며,
  `docs/harness/kickoff-done` 파일을 만들면 꺼집니다. AC 추적까지 원하면 에이전트에게
  "kickoff 해줘"라고 하면 인터뷰로 seed/AC를 만들어 줍니다(선택).
